# ADR-0012: macOS 26 이하의 숨김 — 구분자 확장 + 아이콘 자동 이동

- 상태: ✅ 채택 (2026-11-11 기술 검증 T1~T3 통과, 사용자 확인, 실제 앱에 구현해 macOS 26.5.2에서 동작 확인)
- 날짜: 2026-11-11
- 관련: [ADR-0002](0002-target-macos-27.md) ("macOS 26 이하용 숨김 방식은 만들지 않는다"를 대체) · [ADR-0003](0003-visibility-mechanism.md) · [ADR-0004](0004-reorder-mechanism.md) · [ADR-0005](0005-backend-abstraction-private-api.md) · [platform-notes.md 7절](../architecture/platform-notes.md#7-macos-26에서-확인한-것-)

## 맥락

실제 사용 환경(macOS 26.5.2)에서 앱이 "이 macOS 버전에서는 숨김을 쓸 수 없습니다"로 표시됩니다. 확인해 보니 숨김에 쓰는 비공개 프레임워크(`MenuBarClientCore`)와 `MenuBarAgent` 프로세스가 macOS 26에는 없습니다. [ADR-0002](0002-target-macos-27.md)가 예상만 하고 확인하지 못했던 내용입니다. 즉 지금 앱은 macOS 27에서만 쓸모가 있습니다.

macOS 26의 메뉴바는 아이콘마다 창이 따로 있는 예전 구조입니다. 이 구조에서는 "자기 상태 아이템 하나를 아주 길게 늘여 그 왼쪽의 아이콘을 화면 밖으로 밀어내는" 구분자 확장 방식이 통하고, 이 Mac에서 직접 확인했습니다.

## 결정

**macOS 26 이하에서는 구분자 확장 방식으로 숨기고, 숨길 앱의 아이콘은 앱이 ⌘+드래그를 대신 수행해 구분자 왼쪽으로 옮깁니다.**

1. **백엔드를 실행 시 고릅니다.** 허용 목록 클래스가 있으면 기존 방식(ADR-0003), 없고 macOS 26 이하이면 구분자 방식, 그 밖에는 "지원 안 됨". 판단은 OS 버전 번호가 아니라 기능 유무를 먼저 봅니다.
2. **숨기기·펼치기 = 구분자의 길이 변경.** 이 앱이 보이지 않는 상태 아이템(구분자)을 하나 더 두고, 숨길 때 길이를 10000으로, 펼칠 때 원래대로 바꿉니다. 포인터를 움직이지 않고 즉시 반영됩니다.
3. **무엇을 숨길지는 지금과 같은 설정으로 정합니다** (`Layout.hiddenApps`, 단위는 앱). 숨길 앱의 아이콘이 구분자 오른쪽에 있거나 표시할 앱의 아이콘이 왼쪽에 있으면, 잠깐 펼친 뒤 ⌘+드래그 합성(ADR-0004의 구현)으로 옮기고 다시 숨깁니다.
4. **따라서 macOS 26에서는 숨김에 접근성 권한이 필요합니다.** 권한이 없으면 숨김을 켜지 않고 이유와 권한 허용 버튼을 보여 줍니다.
5. **자기 아이콘이 구분자 왼쪽에 있으면 숨기지 않습니다.** 자기 상태 아이템의 위치는 권한 없이 정확히 읽을 수 있으므로(검증됨) 숨기기 직전에 확인합니다.
6. **처음 범위:** 앱 단위 숨김·펼치기·자동 다시 숨기기. 시스템 아이콘(Wi-Fi·배터리) 숨김은 이 방식에서는 내놓지 않습니다 (macOS 26에서는 시스템 아이콘도 식별자로 구분되어 읽히므로 나중에 추가할 여지는 있음 — 옮겨지는지는 미확인). 시계를 누를 때 숨김을 푸는 처리(ADR-0003의 알림 센터 우회)는 이 방식에서는 끕니다 — 알림 센터를 막는 것은 허용 목록 방식뿐입니다.

### 구조에 생기는 변화

| 모듈 | 변화 |
|---|---|
| `MenuBarDomain` | `VisibilityControlling`에 백엔드의 성질을 알리는 값 추가: 접근성 권한 필요 여부, 시스템 아이콘 숨김 지원 여부, 알림 센터를 막는지. `PauseReason`에 "접근성 권한 필요" 추가. 이동 계획(어떤 아이콘을 구분자 어느 쪽으로 옮길지)은 순수 함수로 두고 단위 테스트 |
| `MenuBarServices` | `SeparatorVisibilityController` 추가 (읽기 → 이동 → 확인의 흐름. OS에 닿지 않아 가짜 메뉴바로 단위 테스트). 숨김을 켤 수 없는 이유에 권한 추가, 권한이 생기면 다시 시도 |
| `MenuBarSystem` | `StatusItemSeparator` 추가 (구분자 아이템 소유, 길이 변경). 비공개 API는 쓰지 않음 |
| `MenuBarUI` · `App` | 권한 안내 문구(한국어·영어·중국어), 시스템 아이콘 구역과 시계 처리를 백엔드 성질에 따라 숨김/끔, 백엔드 선택 |

## 검증 결과 (2026-11-11, macOS 26.5.2)

**권한 없이 확인한 것**

| 확인한 것 | 결과 |
|---|---|
| 구분자 길이 10000 → 왼쪽 아이콘이 화면 밖으로 밀려남, 오른쪽 아이콘은 그대로 | ✅ |
| 길이를 되돌리면 원래 자리로 복구 | ✅ |
| 구분자를 펼친 채 `SIGKILL` → 1초 안에 전부 복구 (fail-open이 구조적으로 보장됨) | ✅ |
| 펼친 동안 새로 생긴 아이콘은 구분자 왼쪽(숨김 쪽)에 놓임 — 허용 목록 방식과 같은 "기본이 차단" | ✅ |
| 자기 상태 아이템의 창 위치가 실제 위치와 일치 | ✅ |
| 어중간한 길이(500)는 다른 아이콘 7개를 함께 사라지게 함 → 길이는 항상 화면 폭보다 훨씬 크게 | ✅ 확인 |

**접근성 권한을 준 검증용 앱으로 확인한 것** — 읽기와 드래그는 제품 코드(`AXItemDiscovery`, `EventSynthesisReorderer`)를 고치지 않고 그대로 썼습니다.

| 숨김 중에 처음 보는 앱이 실행됨 → 숨김 쪽에 놓인 아이콘을 표시 쪽으로 옮김 | ✅ |
| 순서 읽기 → 잠깐 펼쳤다가 다시 숨김, 목록에 구분자가 나오지 않음 | ✅ |
| 숨김 중 `SIGKILL` → 전부 표시로 복구 | ✅ 2초 이내 |
| 앱을 다시 실행해도 구분자가 같은 자리(자기 아이콘 바로 왼쪽)에 놓임 | ✅ |
| 아이콘 여러 개를 옮겨도 서로의 순서가 유지됨 (표시로, 다시 숨김으로) | ✅ 처음에는 뒤집혔고, 고친 뒤 확인 |
| 숨김 중 Apple 메뉴·앱 메뉴 클릭 (T4) | ✅ 열리고 닫힘 |

**구현에서 정한 것**
- 지난번과 같은 허용 목록으로 숨길 때는 구분자부터 늘이고 배치는 그 뒤에 확인합니다 (좌클릭이 바로 반영되도록). 목록이 달라졌으면 배치를 먼저 맞춥니다.
- 여러 아이콘을 옮길 때 서로의 순서가 유지되도록, 숨길 것은 왼쪽 것부터, 표시할 것은 오른쪽 것부터 옮깁니다. (처음에는 순서가 뒤집혔습니다.)
- 옮겨지지 않는 아이콘은 두 번 해 보고 그 실행 동안 건너뜁니다. 자기 아이콘이 숨김 쪽에 남으면 숨기지 않습니다.
- 앱이 실행·종료되면 1.5초·4초 뒤에 배치를 다시 확인합니다 (새 앱이 아이콘을 만들 시간). 옮길 것이 없으면 화면에 변화가 없습니다.
- 켜려고 할 때 권한이 없으면 권한 요청 창을 띄우고, 켜려던 뜻을 저장해 두었다가 허용되는 즉시 숨깁니다. 시작할 때는 요청 창을 띄우지 않습니다.
- 구분자는 접었을 때 내용이 없어 접근성 목록에 나오지 않았습니다. 그래도 나올 경우에 대비해 위치로 알아보고 순서 편집 목록에서 뺍니다.
- `/Applications` 밖의 앱에 붙이던 "숨김 중에는 표시할 수 없음" 표시는 이 방식에서는 붙이지 않습니다.

## 검토한 대안

| | 방식 | 장점 | 단점 | 판단 |
|---|---|---|---|---|
| **A** | **구분자 확장 + 앱이 아이콘을 옮김** | 설정 화면과 사용법이 macOS 27과 같음. 숨기기·펼치기는 즉시 | 접근성 권한 필수. 숨길 앱을 바꿀 때 아이콘이 잠깐 보이고 포인터가 움직임 | **제안** |

| D | 비공개 창 서버 API로 아이콘 창을 직접 옮김 | 포인터가 움직이지 않음 | 창이 제어 센터 소유, 비공개 API가 하나 더 늘어남 | 기각 |
| E | 지금처럼 "지원 안 됨" 유지 | 작업 없음 | macOS 26 사용자는 앱의 핵심 기능을 쓸 수 없음 | 기각 (사용자 요청) |

## 결과

**얻는 것**
- macOS 26에서도 숨김·펼치기·자동 다시 숨기기가 동작합니다.
- 이 방식은 공개 API(`NSStatusItem`, 접근성, `CGEvent`)만 씁니다.
- 크래시·강제 종료 시 구분자가 사라지면서 전부 표시로 돌아옵니다.
- `/Applications` 요건은 이 방식에 기술적으로 필요 없지만, 안내를 하나로 유지하려고 그대로 둡니다.

**감수하는 것**
- **접근성 권한이 없으면 macOS 26에서는 숨김을 쓸 수 없습니다.** (macOS 27에서는 지금처럼 권한 없이 숨김 가능)
- 숨길 앱을 바꾸거나 새 메뉴바 앱이 실행되면 숨긴 아이콘이 잠깐 나타나고 포인터가 잠시 움직입니다. 좌클릭 펼치기·숨기기에서는 일어나지 않습니다.
- 사용자가 직접 ⌘+드래그로 아이콘을 구분자 너머로 옮기면, 다음에 숨길 때 설정대로 되돌립니다 (설정이 기준).
- 숨김 백엔드가 두 벌이 되어, macOS 업데이트마다 두 방식을 모두 확인해야 합니다. macOS 15~25는 확인할 기기가 없습니다.
- 접었을 때 구분자가 폭 16pt의 빈칸으로 남습니다 (길이 0으로 줄여도 최소 폭이 16pt).
