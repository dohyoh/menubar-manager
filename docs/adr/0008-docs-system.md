# ADR-0008: 문서 체계 — Markdown 원본 + 단일 HTML

- 상태: ✅ 채택
- 날짜: 2026-11-10
- 관련: [docs/README.md](../README.md)

## 맥락

문서의 독자는 둘입니다.

1. **개발 중 참조** — 특정 사실을 빠르게 찾아야 함 (AI 코딩 도구 포함). 구조화되어 있고, 검색·부분 수정이 쉬워야 함.
2. **사람이 한 번에 파악** — 처음 보거나 오랜만에 돌아온 개발자가 쉽게, 보기 좋게 전체를 읽어야 함.

두 용도를 한 형식으로 만족시키기 어렵습니다.

## 결정

- **원본은 Markdown.** `docs/` 아래 주제별 폴더(`plan/`, `architecture/`, `adr/`)에 나눠 둡니다. 진입점은 `docs/README.md`.
- **요약본은 HTML 한 장.** `docs/overview.html` 하나만 유지합니다. 외부 리소스 없이 파일 하나로 열립니다.
- HTML을 나눠야 할 만큼 커지면 **폴더당 최대 1개**(`plan/index.html` 등)까지만 허용합니다.
- 내용 변경은 Markdown 먼저, 같은 작업 안에서 HTML의 해당 섹션을 맞춥니다.
- 변경 이력은 `docs/CHANGELOG.md`, 결정은 `docs/adr/`.

## 검토한 대안

| 대안 | 판단 |
|---|---|
| Markdown만 | 참조엔 좋지만 한눈에 보기 어렵고 도식 표현이 약함 |
| HTML만 | 보기 좋지만 부분 수정·검색·diff가 불편 |
| 정적 사이트 생성기 (MkDocs 등) | 빌드 단계와 의존성이 생김. 이 규모에는 과함 |
| Markdown에서 HTML 자동 생성 | 요약본은 원본의 축약·재구성이라 1:1 변환으로는 "쉽게 읽히는 한 장"이 안 나옴 |

## 결과

- HTML은 손으로 맞추는 요약본이라 원본과 어긋날 수 있습니다 → `docs/README.md`의 관리 규칙과 루트 `CLAUDE.md`에 갱신 규칙을 명시합니다.
- HTML에는 세부 사항을 다 넣지 않고, 각 섹션에서 원본 Markdown으로 링크합니다.
