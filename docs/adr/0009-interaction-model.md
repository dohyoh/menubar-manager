# ADR-0009: 상호작용 모델 — 좌클릭 토글, 우클릭 메뉴, 관리는 설정 창

- 상태: ✅ 채택 (사용자 요구, 2026-11-10 · 같은 날 메뉴 구성 수정)
- 날짜: 2026-11-10
- 관련: [requirements.md](../plan/requirements.md) · [ADR-0001](0001-menu-bar-agent-app.md) (패널 부분을 이 ADR이 대체)

## 맥락

최초 기획([ADR-0001](0001-menu-bar-agent-app.md))은 메뉴바 아이콘을 누르면 패널이 열리고, 그 안에서 앱 목록을 토글·정렬하는 구조였습니다. 사용자 검토에서 두 가지 문제가 나왔습니다.

1. 설치·등록된 앱이 많으면 작은 패널에서 목록을 관리하기 어렵다.
2. 가장 자주 하는 동작(숨긴 앱 펼치기/숨기기)에 클릭이 두 번 든다 (아이콘 → 버튼).

## 결정

| 입력 | 동작 |
|---|---|
| 메뉴바 아이콘 **좌클릭** | 숨긴 앱 **펼치기 ↔ 숨기기** 토글. 아이콘 모양으로 현재 상태 표시 |
| 메뉴바 아이콘 **우클릭** (또는 Control+클릭) | 메뉴: **숨기기 스위치** · 설정… · 정보 · 종료 |
| 우클릭 메뉴 > **설정…** | 설정 창. 첫 탭이 **메뉴바 관리** (앱 목록·표시 여부·순서) |

- **패널(팝오버)은 만들지 않습니다.**
- 우클릭 메뉴 구성: **숨기기(스위치)**, 설정…, 정보, 종료. 이후 프로필 전환(M5)이 추가됩니다.
  - "정보"는 주요 기능을 간략히 설명하는 화면을 엽니다 (메뉴바 아이콘 옮기는 방법 포함).
  - 스위치를 켜면 숨김 적용, 끄면 전부 표시를 유지합니다. 스위치로 끈 경우에는 자동으로 다시 숨기지 않습니다.
  - "펼친 뒤 자동으로 다시 숨기기"는 메뉴가 아니라 설정 창에 둡니다.
  - *(2026-11-10 수정: 처음에는 "펼치기/숨기기" 글자 항목, "자동으로 다시 숨기기", "관리 일시 중지"가 메뉴에 있었으나 사용자 검토로 위와 같이 바꿈. "관리 일시 중지"는 스위치 끔이 대신함. 이어서 "정보" 항목을 추가함.)*
- 설정 창의 "메뉴바 관리" 탭은 많은 앱을 다루도록 **검색, 필터(메뉴바에 있는 앱 / 숨긴 앱 / 설치된 앱 전체), 표시·숨김 구역, 드래그 정렬**을 제공합니다.

## 검토한 대안

| 대안 | 판단 |
|---|---|
| 패널 유지 + 검색 추가 | 좁은 폭에 목록·검색·정렬을 다 넣기 어렵고, 좌클릭이 토글로 쓰일 수 없음 → 기각 |
| 좌클릭 = 메뉴, 별도 아이콘 = 토글 (아이콘 2개) | 메뉴바 공간을 줄이려는 앱이 자리를 2칸 차지 → 기각 |
| 좌클릭 = 토글, Option+클릭 = 메뉴 | 발견하기 어려움. 우클릭이 관례에 맞음 → 기각 |

## 결과

- 가장 흔한 동작이 클릭 한 번이 됩니다.
- 관리 화면이 일반 창이 되어 크기 조절·검색·키보드 탐색이 자연스럽습니다.
- `MenuBarUI`에서 `Panel/`이 빠지고 `StatusMenu/`(우클릭 메뉴 구성)와 `Settings/MenuBarManagement/`가 들어갑니다.
- 좌클릭/우클릭 구분은 공개 API(`sendAction(on:)`)로 구현합니다. 검증용 앱에서 실제 클릭으로 동작을 확인했습니다 (좌클릭 토글, 우클릭 메뉴).
- **기본값 가정:** "펼친 뒤 자동으로 다시 숨기기"는 켬(10초)으로 시작합니다. 최초 요구가 "잠깐 노출"이었기 때문이며, 설정 창에서 끌 수 있습니다. 사용자 확인 후 조정합니다.
- 메뉴 안의 스위치는 `NSMenuItem.view`에 `NSSwitch`를 넣어 구현합니다. 검증용 앱에서 표시와 동작을 확인했습니다.
- 트랙패드에서 우클릭이 어려운 사용자를 위해 Control+클릭도 같은 메뉴를 엽니다.
