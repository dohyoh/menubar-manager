# ADR-0010: 설치·실행 위치 — 항상 `/Applications`

- 상태: ✅ 채택 (2026-11-10 M0 검증에서 확인된 제약)
- 날짜: 2026-11-10
- 관련: [platform-notes.md 3.7](../architecture/platform-notes.md#37-applications-요건-️) · [ADR-0003](0003-visibility-mechanism.md) · [ADR-0007](0007-distribution.md)

## 맥락

M0 검증에서, 프로젝트 빌드 폴더나 `~/Applications`에서 실행한 앱은 허용 목록에 자기 번들 ID를 넣어도 **자기 메뉴바 아이콘이 숨겨졌습니다.** `MenuBarAgent`가 그 아이콘의 번들 ID를 nil로 기록하기 때문입니다. 같은 앱을 `/Applications`로 옮기자 정상적으로 매칭되어 아이콘이 유지됐습니다. 숨김 중에 자기 아이콘이 사라지면 사용자가 다시 펼칠 방법이 없으므로 치명적입니다.

## 결정

- **이 앱은 `/Applications`에서만 숨김 기능을 켭니다.**
- 실행 시 자기 위치를 확인하고, `/Applications`가 아니면 숨김을 켜지 않고(`paused` 유지) "응용 프로그램 폴더로 옮겨 주세요" 안내를 표시합니다. (구현됨. 자동으로 옮겨 주는 버튼은 아직 없고 "Finder에서 보기"만 제공)
- **개발 빌드도 `/Applications`에 설치해 실행합니다.** 빌드 스크립트에 설치 단계를 둡니다 (`./scripts/build.sh install`, 구현됨). Xcode에서 바로 실행(⌘R)한 빌드는 숨김 검증에 쓸 수 없습니다.
- ~~숨김을 켠 직후 자기 아이콘이 보이는지 확인~~ → **불가능함을 확인했습니다.** 자기 아이콘이 숨겨져도 앱이 읽을 수 있는 값(창 위치·표시 여부)은 그대로입니다. 대신 ① 설치 위치를 미리 확인해 원인을 막고 ② 응용 프로그램 폴더에서 앱을 다시 열면 설정 창이 뜨도록 해 탈출구를 둡니다.

## 검토한 대안

| 대안 | 판단 |
|---|---|
| 위치 제한 없이 실행 | 자기 아이콘이 사라져 복구 불가 상태가 됨 → 불가 |
| 자기 아이콘이 사라져도 단축키로 복구 | 단축키를 모르면 갇힘. 안전장치로는 부족 → 보조 수단으로만 |
| 개발 시 Xcode 실행 경로를 `/Applications`로 지정 | Xcode 빌드 설정(`CONFIGURATION_BUILD_DIR`)으로 가능하나 권한·정리 문제가 있음 → 스크립트 설치 방식 우선, 필요 시 재검토 |

## 결과

- 배포 시 "앱을 응용 프로그램 폴더로 드래그" 방식(DMG)과 자연스럽게 맞습니다.
- 개발 루프에 "설치" 단계가 하나 늘어납니다. 로직 대부분은 `swift test`로 검증하므로 영향은 OS 연동 확인에 한정됩니다.
- 같은 제약이 **사용자의 다른 앱에도** 적용됩니다: `/Applications` 밖의 앱은 숨김 중 표시할 수 없습니다. 설정 화면의 해당 앱에 이유를 표시합니다.
- 접근성 권한은 경로가 아니라 서명에 묶이므로, 고정 인증서로 서명하면 재설치 후에도 유지됩니다.
