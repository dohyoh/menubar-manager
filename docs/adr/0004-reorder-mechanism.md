# ADR-0004: 순서 변경 방식 — ⌘+드래그 이벤트 합성

- 상태: ✅ 채택 (2026-11-10 M0 2차 검증 S5·S6·S7 통과, 실제 앱에 구현)
- 날짜: 2026-11-10
- 관련: [platform-notes.md](../architecture/platform-notes.md) · [roadmap.md M0](../plan/roadmap.md#m0--기술-검증--기반-구축) · [ADR-0003](0003-visibility-mechanism.md)

## 맥락

FR-3(순서 조정)을 위해 다른 앱의 메뉴바 아이템 위치를 프로그램으로 바꿔야 합니다. 공개 API는 없습니다. macOS는 사용자가 ⌘을 누른 채 아이템을 드래그하면 순서를 바꿔 주고, 이 동작이 macOS 27.2.1에서도 되는 것을 사용자가 직접 확인했습니다 (2026-11-10).

macOS 26까지의 관리 앱들은 아이템별 창을 대상으로 ⌘+드래그 이벤트를 합성했습니다. macOS 27에는 아이템별 창이 없고 창 목록으로 다른 앱의 아이템 위치를 알 수 없음을 확인했습니다. 아이템 위치를 다른 방법으로 알아내 **화면 좌표 기준**으로 합성해야 합니다.

숨겨진 아이템(FR-3a)은 메뉴바에 없으므로 직접 옮길 수 없습니다.

## 결정

**접근성 API로 아이템 좌표를 얻고, ⌘+마우스 드래그 이벤트를 합성해 옮깁니다.**

- 아이템 열거·좌표: 각 앱의 접근성 요소 `AXExtrasMenuBar`의 자식
- 이동: `CGEvent`로 ⌘+마우스 누름 → 이동 → 놓음을 합성
- 숨겨진 아이템 순서: **잠시 전부 표시 → 이동 → 다시 숨김** 으로 처리 (해제·재적용이 1초 안에 되고 깜빡임 없이 교체됨을 확인)
- 이동 횟수는 최소화합니다 (현재 순서와 목표 순서의 최장 증가 부분수열을 고정하고 나머지만 이동)
- 이동마다 재조회로 결과를 확인합니다

## 검토한 대안

| | 방식 | 장점 | 단점 | 판단 |
|---|---|---|---|---|
| **A** | **⌘+드래그 이벤트 합성** | 시스템이 공식 지원하는 사용자 동작을 재현 — 결과가 시스템에 정상 저장됨 | 접근성 권한 필요. 이동 중 포인터가 움직임. 타이밍에 민감. 숨김 아이템은 노출 후에만 가능 | **1순위** |
| B | 각 앱의 `NSStatusItem Preferred Position …` 값 변경 | 화면 조작 없음 | 남의 앱 설정을 고침, 앱 재시작 필요, macOS 27이 이 값을 쓰는지 불명 | S6 실패 시 조사 |
| C | 비공개 `MenuBarClient` (`MBEditModeAssertion`, 드래그 관련 클래스) | 시스템 경로로 직접 이동 가능성 | 용도·사용법 불명, 조사 비용 큼 | 여유 있을 때 조사 |
| D | 프로그램으로 옮기지 않고 사용자의 ⌘+드래그를 안내·기록만 | 구현 단순, 권한 불필요 | "패널에서 조정"이라는 요구사항 미충족 | 최후 대안 |

## 결과

**얻는 것**
- 사용자가 손으로 한 것과 같은 결과 → 시스템이 순서를 기억하고 재부팅 후에도 유지될 것으로 기대 (S6에서 확인).

**감수하는 것**
- **접근성 권한**이 필수가 됩니다 → 온보딩에서 이유를 설명하고, 없으면 순서 변경만 비활성화.
- 이동 중 잠깐 포인터가 움직이고, 숨김 아이템을 옮길 때는 메뉴바가 잠시 펼쳐집니다 → `reordering` 상태로 묶어 짧게 끝내고, 끝나면 포인터를 원위치.
- 시스템 고정 아이템(시계 등)은 옮길 수 없습니다 → 목록에서 "이동 불가"로 표시.

**설계에 미치는 영향**
- 이동 계획 계산(`MovePlanner`)은 순수 함수로 Domain에 두고 단위 테스트합니다.
- 사용자가 직접 ⌘+드래그로 순서를 바꾸면 이를 감지해 레이아웃에 반영해야 합니다 (그렇지 않으면 다음 적용 때 되돌려 버림).

## 검증 결과 (2026-11-10, macOS 27.2.1)

| 확인한 것 | 결과 |
|---|---|
| 접근성 API로 아이템 위치 읽기 | ✅ 단, 표시되지 않는 아이템은 예전 좌표를 돌려줘서 "그 좌표에 실제로 있는지" 확인해 걸러야 함 |
| ⌘+드래그 합성으로 순서 변경 | ✅ 단, 천천히 끌어야 함 (6pt마다 한 걸음, 12ms 간격, 놓기 전 250ms) |
| 숨긴 아이템 순서 변경 | ✅ 잠깐 펼침 → 이동 → 다시 숨김 |
| 서드파티 아이콘을 시스템 아이템 사이로 이동 | ✅ |
| 모니터 두 대 | ✅ 모니터 오른쪽 끝 기준 거리로 정규화해 해결 |
| 재부팅 후 순서 유지 | ✅ 재부팅 전후 순서 동일 |

상세는 [platform-notes.md 3.21~3.23](../architecture/platform-notes.md#321-접근성으로-메뉴바-아이템-읽기--s5).

**구현에서 정한 것**
- 순서는 저장하지 않습니다. 시스템이 기억하는 순서를 매번 새로 읽습니다.
- 시스템 아이템(시계, 제어 센터 등)은 옮기지 않습니다. 이동 계획을 세울 때 "고정"으로 두고 나머지만 옮깁니다.
- 한 번 옮길 때마다 다시 읽어 결과를 확인하고, 두 번 연속 변화가 없으면 포기하고 실제 순서를 보여 줍니다.
- 화면은 설정 창의 별도 탭 "순서"에 둡니다. 읽기와 적용은 사용자가 버튼을 눌렀을 때만 합니다 (숨긴 아이콘이 잠깐 나타나고 포인터가 움직이기 때문).
