# ADR-0002: 지원 OS — 앱은 macOS 15부터 실행, 숨김은 시스템 기능이 있는 버전에서만

- 상태: ✅ 채택 (2026-11-10 사용자 확인: "큰 수정이 없는 한도 내에서 지원"). **"macOS 26 이하용 별도 숨김 방식은 만들지 않습니다"는 [ADR-0012](0012-separator-visibility-macos26.md)로 대체됨 (2026-11-11)** — 최소 실행 버전과 "기능 유무를 실행 시 확인"은 그대로 유효
- 날짜: 2026-11-10
- 관련: [platform-notes.md](../architecture/platform-notes.md) · [ADR-0003](0003-visibility-mechanism.md) · [ADR-0005](0005-backend-abstraction-private-api.md)

> 파일명은 처음 제안("macOS 27 이상만")의 흔적입니다. 결정 내용은 아래와 같이 바뀌었습니다.

## 맥락

macOS 27에서 메뉴바 구조가 바뀌어, 숨김에 쓰는 시스템 기능(허용 목록)은 macOS 27에서 확인된 것입니다. macOS 26 이하에서는 메뉴바 구조가 달라 완전히 다른 방식(아이템 창 조작, 구분자 확장)이 필요합니다. 개발·검증 환경은 macOS 27.2.1 한 대뿐입니다.

사용자 방침: **큰 수정이 없는 한도 내에서** 다른 macOS 버전도 지원한다.

## 결정

- **배포 대상(최소 실행 버전)은 macOS 15.0.** 앱 자체는 그 이상에서 실행됩니다.
- **숨김 기능은 실행 시점에 필요한 시스템 기능이 있는지 확인해서 켭니다** (OS 버전 번호로 가르지 않음). 있으면 동작하고, 없으면 앱은 실행되되 숨김이 꺼진 상태로 "이 macOS 버전에서는 숨김 기능을 쓸 수 없습니다"를 표시합니다.
- **macOS 26 이하용 별도 숨김 방식은 만들지 않습니다.** "큰 수정"에 해당하기 때문입니다.

## 검토한 대안

| 대안 | 판단 |
|---|---|
| macOS 27 이상만 (처음 제안) | 가장 단순하지만, 구버전에서 실행조차 안 됨. 사용자 방침과 다름 |
| macOS 26 이하용 숨김 백엔드를 따로 구현 | 구현·검증이 두 벌, 검증용 기기 필요 → "큰 수정"이라 보류 |
| **실행은 넓게, 숨김은 기능 유무로 판단** | 추가 비용이 거의 없음 (자가진단은 어차피 필요). **채택** |

## 결과

- **확인된 것:** macOS 27.2.1에서 전체 기능 동작.
- **확인하지 못한 것:** macOS 15~26에서의 실행과 표시. 이 버전들에서는 숨김이 꺼진 채로 실행될 가능성이 높습니다 (시스템 기능이 없을 것으로 예상). 실제 기기에서 확인한 적은 없습니다.
- macOS 27의 이후 버전(27.x, 28)에서 시스템 기능이 사라지거나 바뀌면 같은 경로로 "쓸 수 없음" 상태가 되어 아이콘을 잃지 않습니다 (fail-open).
- 백엔드가 프로토콜로 분리되어 있어([ADR-0005](0005-backend-abstraction-private-api.md)), 나중에 구버전용 구현을 추가하는 길은 열려 있습니다.
- 사용하는 공개 API(SMAppService, Observation, SwiftUI)는 모두 macOS 15에서 쓸 수 있습니다.
