프로젝트 개요 · 가칭

메뉴바에 무엇을 보일지 고르고, 클릭 한 번으로 펼치고 접는 앱

macOS 상단 메뉴바에 상주하면서, 아이콘이 많아 복잡해진 메뉴바를 앱 단위로 숨기고, 필요할 때 펼쳐 보고, 순서를 정리할 수 있게 해 줍니다.

버전 1.0.2 배포 · M4까지 구현 macOS 15+ 실행 · 숨김은 27과 26.5에서 확인 Swift 6 · SwiftUI + AppKit 제품 코드 약 4,400줄 · 테스트 130개

1무엇을 만드나

완성됐을 때의 사용 방식을 흉내 낸 모형입니다. 메뉴바의 초록 아이콘을 좌클릭·우클릭해 보고, 아래 설정 창에서 스위치를 바꿔 보세요.

숨긴 앱 펼치기 / 숨기기
메뉴바의 이 앱 아이콘을 좌클릭합니다. 다시 누르면 숨습니다.
숨기기 켜고 끄기
아이콘을 우클릭한 뒤 "숨기기" 스위치를 사용합니다. 끄면 다시 켤 때까지 모두 표시합니다.
숨길 앱 고르기
우클릭 > 설정…에서 앱별 스위치를 끕니다. 앱이 많으면 검색과 필터로 찾습니다.
자동으로 다시 숨기기
설정 창에서 켜 두면, 좌클릭으로 펼친 뒤 정한 시간(기본 5초)이 지나면 다시 숨깁니다.
메뉴바 아이콘 옮기기
⌘(Command) 키를 누른 채 메뉴바의 아이콘을 좌우로 드래그합니다. 숨긴 앱은 먼저 펼친 다음 옮깁니다.
알아 둘 점
응용 프로그램 폴더 밖의 앱과 제어 센터에서 꺼낸 항목은 숨김 중에는 표시되지 않습니다. 앱을 종료하면 숨긴 아이콘은 모두 돌아옵니다.

모형입니다. 실제 앱에서는 메뉴바 관리 아래쪽의 "순서 편집"을 누르면 같은 자리의 목록이 메뉴바 순서로 바뀌고, 끌어서 순서를 바꿉니다. 점선 표시는 펼쳤을 때만 보이는 숨긴 아이템입니다.

입력동작
아이콘 좌클릭숨긴 앱 펼치기 ↔ 숨기기. 아이콘 모양이 현재 상태를 보여 줍니다.
아이콘 우클릭 Control+클릭메뉴 — 숨기기 스위치, 설정…, 정보, 종료. 스위치를 끄면 전부 표시한 채로 유지됩니다 (자동으로 다시 숨기지 않음).
메뉴 > 설정…설정 창의 메뉴바 관리에서 앱별 표시 여부와 순서를 정합니다. 검색·필터가 있어 앱이 많아도 관리할 수 있습니다. "펼친 뒤 자동으로 다시 숨기기"는 일반 탭에서 켜고 끄고, 시간을 고릅니다 (3~60초, 기본 10초).
메뉴 > 정보주요 기능을 한두 문장씩 설명합니다. 메뉴바 아이콘 옮기는 방법(⌘을 누른 채 드래그)도 여기서 안내합니다.

"위젯"이라고 부르지만 실제 형태는 메뉴바 상주 앱입니다. 데스크탑에 놓는 WidgetKit 위젯은 메뉴바를 제어할 수 없습니다 (ADR-0001). 처음에는 아이콘을 누르면 패널이 열리는 구조였으나, 앱이 많으면 관리가 어렵다는 검토 의견에 따라 위 방식으로 바꿨습니다 (ADR-0009).

3기술 검증 결과

macOS에는 다른 앱의 메뉴바 아이콘을 숨기거나 옮기는 공개 API가 없습니다. 그래서 만들기 전에 이 Mac(macOS 27.2.1)에서 실제로 되는지부터 확인했습니다.

결론: 요청된 기능이 모두 이 Mac에서 동작합니다. 숨기기·펼치기는 권한 없이 되고, 앱이 강제 종료돼도 시스템이 아이콘을 자동으로 되돌려 줍니다. 순서 변경은 접근성 권한을 허용하면 됩니다.

확인한 것결과상태
허용 목록 방식으로 앱 아이콘 숨기기목록에 없는 앱의 아이콘이 1초 안에 사라짐. 권한 불필요통과
해제·종료·강제 종료 시 복구모두 자동 복구 (강제 종료 후 2초 이내)통과
숨김 중 자기 아이콘 유지유지됨 — 단, 앱이 응용 프로그램 폴더에 있을 때만통과
숨김 목록을 깜빡임 없이 변경새 제한을 켠 뒤 이전 것을 해제하면 매끄럽게 교체됨통과
시스템 아이콘 개별 제어배터리·시계·Wi-Fi·제어 센터를 번호로 제어 가능통과
좌클릭/우클릭 구분검증용 앱 아이콘을 직접 클릭해 확인 — 좌클릭은 토글, 우클릭은 메뉴통과
설정 창에서 앱 고르기스위치를 끄면 숨김 중에도 즉시 반영. 단, 권한 없이는 아이콘이 없는 일반 앱도 목록에 섞임통과

모니터 두 대에서 순서 읽기아이템마다 좌표의 기준 모니터가 달라 순서가 섞였음 → 모니터 오른쪽 끝 기준 거리로 바꿔 해결통과

검증 중 새로 알게 된 제약

응용 프로그램 폴더 요건

앱이 /Applications에 있어야 시스템이 그 앱의 아이콘을 알아봅니다. 다른 위치에서 실행하면 허용해도 숨겨집니다. 이 앱 자신은 반드시 그곳에 설치해야 하고, 그 밖에 있는 사용자의 다른 앱은 숨김 중에 표시할 수 없습니다. (ADR-0010)

제어 센터 모듈은 항상 숨겨짐

제어 센터에서 메뉴바로 꺼낸 모듈(타이머 등)은 숨김 중에는 보이지 않습니다. 펼치면 다시 보입니다.

기본이 "차단"

허용 목록에 없는 앱은 숨겨집니다. 새 앱이 실행되면 목록을 갱신해야 그 아이콘이 보입니다.

단위는 앱

한 앱이 아이콘을 여러 개 가질 때 일부만 숨길 수는 없습니다.

숨김 중에는 알림 센터가 닫혀 있음

숨김이 걸려 있으면 시스템이 알림 센터를 열지 않고, 숨김을 유지한 채 여는 방법도 없습니다. 그래서 시계를 누르면 앱이 숨김을 잠깐 풀어 열리게 하고(그동안 숨긴 아이콘도 함께 보임), 닫으면 곧바로 다시 숨깁니다. 트랙패드 쓸기·단축키로는 열리지 않으니 먼저 펼쳐야 합니다.

배경 — macOS 27에서 바뀐 것

macOS 27은 메뉴바 전체를 MenuBarAgent 프로세스의 창 하나로 그립니다. 아이콘마다 창이 따로 있던 예전 구조가 사라져, Ice·Bartender 같은 기존 관리 앱이 쓰던 방법(아이콘 창 옮기기, 긴 구분자로 밀어내기)은 통하지 않습니다. 대신 시스템 안에 "허용한 앱의 아이콘만 남기는" 비공개 기능이 있고, 이것을 사용합니다.

macOS 26 이하에서는 — 다른 방식으로 숨김

macOS 26.5.2에서 확인해 보니 위의 비공개 기능과 MenuBarAgent가 없습니다. 그래서 1.0.2는 이 버전에서 "숨김을 쓸 수 없음"으로 표시합니다 (판정은 정상). macOS 26은 아이콘마다 창이 있는 예전 구조라 긴 구분자로 밀어내는 방식이 통합니다. 앱이 시작할 때 이 Mac에 있는 기능을 보고 방식을 고르도록 구현했고, 아직 릴리스에는 들어가지 않았습니다 (ADR-0012). 이 방식에서는 숨길 앱의 아이콘을 앱이 옮겨야 해서 숨기기에도 접근성 권한이 필요합니다.

접근성으로 아이콘과 소유 앱 읽기macOS 27과 같은 방법으로 15개 모두 읽힘 (제품 코드 수정 없이). 숨겨진 아이콘은 실제 화면 밖 좌표로 읽혀, 펼치지 않고도 판별 가능통과
⌘+드래그를 대신 수행해 구분자 너머로 옮기기양방향, 다른 앱의 아이콘 포함. 한 번에 약 1.3초. 검증 뒤 원래 순서로 되돌림통과
실제 앱(제품 코드)에서 숨기기·펼치기·숨길 앱 변경·새 앱 실행·순서 읽기동작. 숨기기 켜기 4.6초(아이콘 3개 이동 포함), 펼치기 즉시, 다시 숨기기 0.4초. 강제 종료하면 2초 안에 전부 표시통과
숨김 중 앱 메뉴 클릭, 아이콘 여러 개의 순서 유지Apple 메뉴와 앱 메뉴가 정상으로 열리고 닫힘. 여러 아이콘을 옮겨도 서로의 순서가 그대로 (처음에는 뒤집혀서 고침)통과
재부팅 후 위치 유지, 모니터 두 대, macOS 15~25쓰면서 확인 (macOS 15~25는 검증 기기 없음)남음

4동작 방식

핵심 동작이 내부에서 어떻게 처리되는지입니다. 상세 흐름은 architecture/overview.md.

FR-2

  3. 숨김을 켜기 전에 설치 위치와 시스템 기능을 확인
  4. 설정의 자동 숨기기가 켜져 있으면 타이머 후 다시 숨김
FR-1 · FR-17

설정에서 앱 숨기기

  1. 메뉴바 관리에서 스위치를 끔
  2. "숨길 앱" 목록에 저장
  3. 허용 목록 = 실행 중·설치된 앱 − 숨길 앱 + 자기 자신
  4. 숨김 상태면 깜빡임 없이 교체

  2. "적용" → 잠시 전부 펼침
  3. 최소 이동만 골라 ⌘+드래그를 대신 수행 (시스템 항목은 그대로)
  4. 옮길 때마다 다시 읽어 확인 → 다시 숨김

5구조

원칙은 하나입니다. macOS에 닿는 코드는 한 모듈에 가두고, 나머지는 그 모듈을 모른다. OS가 바뀌면 그 모듈만 고칩니다.

App실행 파일. 부품을 조립하고, 메뉴바 아이콘의 좌클릭·우클릭을 받고, 설정 창을 엶
▼
MenuBarUISwiftUI — 우클릭 메뉴, 설정 창(메뉴바 관리·일반), 권한 안내
▼ 의도 전달 · ▲ 상태 읽기
MenuBarServices앱의 두뇌. MenuBarCoordinator가 상태를 혼자 소유. 저장, 자동 숨기기 타이머, 앱 목록, 단축키
▼ 프로토콜로만 의존
MenuBarDomain모델과 순수 규칙(허용 목록 계산, 검색·필터, 이동 계획), 프로토콜 정의. Foundation만 사용 → 테스트 쉬움
MenuBarSystemOS 접점 전부 — 허용 목록 적용, 앱·아이템 조회, 이벤트 합성, 권한, 설치 위치 확인. 비공개 API는 이 안의 브리지에만

앱의 상태

paused전부 표시 유지. 메뉴의 숨기기 스위치 끔·시작 직후·오류
collapsed숨김 적용 중. 평소 상태
expanded좌클릭으로 잠깐 펼침. 다시 누르거나 타이머로 collapsed로
reordering순서를 읽거나 바꾸는 중. 끝나면 이전 상태로

어느 상태에서든 문제가 생기면 paused(전부 표시)로 돌아갑니다. 이것이 fail-open 원칙입니다. 앱이 죽어도 시스템이 숨김을 풀어 주는 것을 검증에서 확인했습니다. 메뉴바 아이콘이 보이지 않을 때는 응용 프로그램 폴더에서 앱을 다시 열면 설정 창이 뜹니다.

6프로젝트 폴더

실제 구조입니다. 파일 단위 설명과 컨벤션은 project-structure.md.

1110_menubar_manager/
├── CLAUDE.md                  작업 규칙 요약
├── project.yml                XcodeGen 프로젝트 정의 (.xcodeproj는 생성물)
├── App/                       앱 타깃 — 얇게: 조립, 아이콘 좌/우클릭, 설정 창 열기
├── Packages/MenuBarKit/       대부분의 코드가 여기 (로컬 Swift Package)
│   ├── Sources/
│   │   ├── MenuBarDomain/         모델 · 규칙 · 프로토콜
│   │   ├── MenuBarServices/       Coordinator · 저장 · 타이머 · 앱 목록
│   │   ├── MenuBarSystem/         OS 접점 (여기에만 OS 의존 코드)
│   │   ├── MenuBarPrivateBridge/  비공개 API 호출 (Objective-C)
│   │   └── MenuBarUI/             우클릭 메뉴 · 설정 창
│   └── Tests/                 swift test 로 실행
├── Spikes/                    기술 검증용 코드 (제품에 포함 안 됨)
│   └── MenuBarSpike/              숨김·좌/우클릭 검증용 앱
├── scripts/                   bootstrap · build(install/run) · strings · make-icon
└── docs/                      문서 (이 파일 포함)

빌드와 설치는 ./scripts/build.sh install, 테스트는 swift test --package-path Packages/MenuBarKit, 번역 누락 검사는 python3 scripts/strings.py check 입니다.

개발할 때 주의: 숨김 동작은 /Applications에 설치한 빌드로만 확인할 수 있습니다. Xcode에서 바로 실행하면 숨김을 켰을 때 앱 자신의 아이콘이 사라집니다.

7개발 계획

위험한 것부터 확인하고, 마일스톤마다 직접 써 볼 수 있는 앱이 나오도록 나눴습니다. 체크리스트와 완료 기준은 roadmap.md.

  1. M0

    기술 검증 완료

    숨김·복구·자기 아이콘 유지·좌/우클릭, 접근성으로 아이템 위치 읽기, 드래그 합성으로 순서 변경까지 확인.

  2. M1

    앱 뼈대 FR-4 · FR-16 · FR-18 · FR-20 구현

    메뉴바 아이콘과 좌/우클릭, 우클릭 메뉴(숨기기 스위치·설정·정보), 설정 창 골격, 정보 화면, 로그인 시 실행, 설치 위치 확인.

  3. M2

    표시/숨김 + 펼치기 FR-1 · FR-2 · FR-5 · FR-6 · FR-17 구현

    숨김, 메뉴바 관리 화면(검색·필터·표시/숨김 구역), 새 앱 정책, 사용 중에는 자동 숨기기 미루기, 첫 실행 안내, 한국어·영어 문자열, 앱 아이콘.

  4. M3

    순서 조정 FR-3 구현

    순서 편집(처음에는 별도 탭, 지금은 메뉴바 관리 안): 순서 읽기, 목록 드래그, 적용. 숨긴 앱 포함, 시스템 항목은 고정, 모니터 두 대 대응. 직접 드래그해 적용하는 조작까지 확인됨.

  5. M4

    안정화·편의 FR-7 ~ FR-9 · FR-19 · FR-21 구현

    화면 언어 선택, 전역 단축키, 자가진단·진단 정보, 설정 백업, 시스템 아이콘 숨김, 알림 센터 열기, "메뉴바" 필터, 새 앱 "묻기", 응용 프로그램 폴더로 옮기기. 노치·전체 화면·잠자기 같은 환경별 점검은 남음.

  6. M5

    확장 FR-10 ~ FR-13 다음

    프로필, 자동 전환, 검색, 조건부 표시. 필요한 것만 골라서.

  7. M6

    배포 FR-15 일부

    1.0.2까지 GitHub Releases에 올림 (공증 없음 — 처음 열 때 경고를 풀어야 함). 저장소 README와 사용 안내서는 영어·한국어·중국어. 공증, 자동 업데이트, 설치 파일(DMG), 라이선스는 남음.

  8. M7

    macOS 26 이하에서 숨김 FR-1 · FR-2 · FR-5 구현

    macOS 26에는 허용 목록 기능이 없어 긴 구분자로 밀어내는 방식을 추가. 숨길 앱의 아이콘은 앱이 옮김(접근성 권한 필수). macOS 26.5.2에서 확인했고, 재부팅·모니터 두 대 확인과 릴리스는 남음 (ADR-0012).

직접 확인이 남은 것

프로그램으로는 확인하기 어렵거나, 쓰는 중인 화면을 방해하게 되어 남겨 둔 항목입니다.

확인할 것방법문제가 있으면
전역 단축키를 직접 기록해 쓰기설정 > 일반 > 전역 단축키에서 조합을 기록하고 눌러 보기기록 화면 또는 등록 방식을 조정
설정 내보내기·가져오기설정 > 일반 > 백업에서 파일로 저장하고 다시 불러오기파일 형식·적용 순서를 조정
새 앱 "묻기", 응용 프로그램 폴더로 옮기기 버튼정책을 "묻기"로 두고 메뉴바 앱을 새로 실행 / 다른 위치에서 앱 실행감지 시점·복사 방식을 조정
폭이 넓은 아이콘(글자가 있는 것)의 순서 변경순서 편집에서 그 아이콘을 옮겨 적용놓는 위치 계산을 조정

9리스크

리스크가능성영향대응
